## 2. 项目一句话

PC 网页版抖音的推荐流过滤扩展：用抖音接口返回的官方字段（`music.id`、`music.title`、`author.nickname`、`text_extra.hashtag_name`）判断视频是否命中屏蔽规则，命中就在 feed 响应到达页面之前删掉，让用户感觉「这个视频根本不存在」，而不是「程序替我划走」。

## 3. 需求演变（用户决策时间线）

### 9/5 上半夜：从调研到第一版

1. 原始需求：屏蔽某个 BGM，让用了它的视频不出现在推荐流；抖音已标记部分视频 BGM，但覆盖不全，需要额外标识能力。先调研现成项目，再规划工作量。
2. 在「油猴脚本 vs 浏览器扩展」之间选了**扩展**（PC 场景，觉得油猴不稳定）。
3. 第一版只覆盖**抖音官方已标识 BGM**的视频。
4. 要求「尽可能对用户无感」，不要做成自动往下滑。
5. 追加需求：屏蔽指定**博主**和**标签**，并在视频上提供一个屏蔽按钮。
6. 按钮交互定型：位置在视频内容右上角、与点赞等原生图标在 X 轴对齐，复用抖音「不感兴趣」的**心形图标**作为入口。
7. 面板结构定型：**三行**——第一行博主、第二行标签、第三行 BGM，可多选并一次性屏蔽，底部是「屏蔽」「取消」。
8. 细节要求：去掉复选框方框，改为选中高亮；去掉「最近识别」区块；按钮图标可在扩展设置页里换。

### 9/5 下半夜：架构原则确立 + 一次严重回归

9. 遇到直播识别异常：直播被识别成「后面某个视频」的内容。修复方向是直播不参与识别，且**不用预加载的下一条视频数据兜底**。
10. 出现「屏蔽后继续下划全是黑屏」，由此确立核心原则：
    - 屏蔽只在**数据层**，尽量不碰显示相关代码；
    - 一批全被屏蔽时，页面表现为「划不动 / 正在加载下一个视频」，等下一批到达即可继续，**尽可能用抖音原版方式解决**；
    - 扩展不代替抖音发请求，也不合成滑动事件。
11. 更名为「**抖音视频屏蔽**」，并对齐原生操作栏视觉。
12. 中途上线过一版改动导致**推荐页一直加载中、视频点不开、精选页点封面无反应**。用户连续三轮坚持「确定是插件的问题」，先回退到「去掉界面」的纯数据层版本（即后来保留的 `douyin-video-block-noui-extension` 0.4.x）确认问题消失，再回到完整版。
13. 回归修复的关键手法（写进了 0.4.5 说明）：不再构造新的 `Response`，只在必要时代理原响应的 `text()` / `json()`；不再劫持 XHR 的 `onload` / `onreadystatechange` 赋值。

### 9/12：记录、图标、精选页、发布

14. 增加**屏蔽记录**：显示作者 + 标题（原始的「作者创作的原声」太长、含抖音官方命名，要去掉），一行日期就够（浏览器自带的 tag 文本被视为多余）。
15. 记录条目改为**整条可点击**，点击打开对应视频；不要单独的「打开」按钮。
16. BGM 名与左下角「汽水音乐」偶尔对不上；抖音对版权音乐做过类似听歌识曲的标记，用户提问要不要把这类也显示出来、什么时候会出现（**未落实**）。
17. 图标方案改版：去掉固定图标选择，改为**用户从本地选一张图**，自动等比缩放到固定像素；扩展管理页与页面内图标都要**无底图、只有图案**，颜色同步、灰阶（贴近 Chrome 官方，但不要纯黑白）。
18. 默认图标：用户分析并提供了抖音「不感兴趣」的碎心 SVG path，最终定为灰阶碎心。
19. 精选页（`/jingxuan?modal_id=...`）一直识别不到视频信息，且点击屏蔽会卡住；期间还出现过「网页打不开」和 `content-isolated.js:797`、`:617` 报错。
20. 咨询发布：给了 Chrome Web Store 上传流程与材料清单，并评估「修改抖音网页的扩展能否过审」——结论是可以发但有拒审风险（名称含「抖音」的商标风险、需声明非官方、要说明为什么需要 `storage` 和 `https://*.douyin.com/*`、自动发送 `R` 快捷键模拟用户操作可能被审核质疑，建议改成可选且默认关闭）。
21. 按钮定位几轮反复：先按点赞图标坐标算 → 插入原生操作栏容器（0.5.16）→ 用户要求「不要放进点赞的容器，只是让 X 轴算得一样」→ 回到独立定位（0.5.17：Y 在视频画面顶部，X 对齐点赞中心）。
22. 顺手借用用户已安装的两个 skill：`chrome-extensions`（扩展开发规范）与 `modern-web-guidance`（现代前端实践）；也解释了 skill 的注入机制与 `.agents\skills` 目录的性质（工具链约定，不是跨平台标准）。

### 9/16：收尾

23. 反馈精选页依旧卡住、无法识别、中间提示「正在加载下一个视频」→ 发布 0.5.19（见下）。
24. 要求**压缩对话历史**（省 token）并**为项目做 git 版本管理** —— 也就是这份文档和这个仓库的由来。

## 4. 技术架构

```text
抖音返回推荐流响应
        │
        ├── content-main.js（MAIN world, document_start）
        │     劫持 fetch / XHR → 识别 feed 接口 → 提取 aweme 条目
        │     → 对照本地屏蔽规则 → 命中条目从响应里删除 → 交回页面
        │     整批全命中 → 返回空列表 + 保留 cursor / has_more → 预取下一批（有限次，失败回退）
        │     通过 window.postMessage 把条目信息发给隔离世界
        │
        └── content-isolated.js（隔离世界, document_start）
              工具栏屏蔽按钮 + 三行选择面板 + 屏蔽记录
              chrome.storage.local 读写（规则、开关、图标、记录）
              精选页 / modal 页的 SSR 兜底解析（decodeURIComponent + 脚本内 JSON 片段提取）
              按钮定位（Y = 视频画面顶部，X = 点赞图标中心）
        │
        └── popup.html / popup.js / popup.css
              屏蔽规则管理、屏蔽记录、按钮图片上传与尺寸设置
```

字段来源（官方字段优先，不猜）：

- BGM：`music.id`、`music.title`
- 博主：`author.nickname`（+ 作者 ID）
- 标签：`text_extra.hashtag_name`、描述里的 `#tag`

关键实现细节：

- `content-main.js` 只处理匹配抖音视频接口的 URL（针对 `aweme/v1/web/...feed` 一类路径），避免误改精选页 / 其它接口导致卡住。
- 响应体改写不再构造新 `Response`，只在需要时包装 `text()` / `json()`，保留原响应上下文。
- XHR 不劫持 `onload` / `onreadystatechange` 的赋值，用事件监听替代。
- 精选页的视频详情在 URL 编码的数据段里，需要 `decodeURIComponent` 后再做 `"awemeId":"..."` 片段匹配，并从 `authorInfo` 起截取块解析。
- 识别失败不再标记为「已请求过」，允许再次点击重试。
- 存储调用前检查 `chrome.storage.local` 是否可用，扩展重载后旧页面不会抛错。

- 直播跳过、不误用预加载数据兜底。

### 已知问题（待处理）

1. ~~精选页 / `modal_id` 详情页卡住且识别不出来~~ —— **0.5.20 已定位并修复**，根因两条：
   - `content-main.js` 的 `extractSsrEntriesForAwemeId` 用 `regex.exec` 循环、又在循环体里手动把 `lastIndex` 写回下一个匹配位置，只要命中一次就会永远取到同一个匹配，**死循环把页面主线程挂死**（表现就是「点击后卡住、刷新也没用」）。
   - `block.search(/"authorInfo"\\s*:/)` 与 `/"music"\\s*:/` 两处正则字面量把 `\s` 写成了 `\\s`（匹配反斜杠而不是空白），所以作者和 BGM 永远找不到 → 面板一直显示「未识别」。
   附带修掉：第一次点击时面板用的是解析前的旧数据（解析是同步的，但渲染顺序反了）；`/video/<id>` 地址只认 `modal_id` 查询参数。
   **验证方式**：用下面的自动调试环境跑精选页 + 点击按钮，面板能显示完整博主/标签/BGM，长任务 0 ms。
2. **按钮定位**：0.5.17 之后未确认。目标很明确——Y 轴在视频画面顶部，X 轴只跟点赞图标中心对齐，要不要插入原生容器由实现自行决定。
3. **控制台报错** `content-isolated.js:797`、`content-isolated.js:617`：定位为扩展重载后旧页面的存储上下文失效，0.5.18 加了保护，需确认真机不再出现。
4. **BGM 名与「汽水音乐」显示不一致**：用户提出过是否要把抖音的版权音乐标记也显示出来，未落实。
5. **音频指纹识别**：用户最早提过「抖音只标记了部分视频 BGM，还需要额外的标识功能」，当前完全不支持，只覆盖抖音已返回 BGM 字段的视频。
6. 未登录的独立配置里，`/video/<id>` 页面没有播放器、也没有 `data-e2e-vid`，工具栏会隐藏；需要在已登录环境下再回归一次。

### 自动复现与抓错（不用麻烦用户截图控制台）

`work/cdp-debug.js` 用 CDP 驱动一个**独立浏览器**（独立临时配置目录，不影响用户日常浏览），加载本扩展、打开指定页面，并把现场写进报告：

```powershell
node work/cdp-debug.js --chrome="C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --url="https://www.douyin.com/jingxuan?modal_id=7684253090765180179" --seconds=15 --click
```

报告包含：控制台报错 / 未捕获异常 / 失败请求 / 长任务（卡顿毫秒数）/ 按钮与面板状态 / 面板实际文字。产物在 `work/logs/<时间戳>/report.md`。

探针（`--probe=`）：

| 探针 | 作用 |
| --- | --- |
| `ssr` | 页面里 SSR 脚本的真实结构：哪些脚本包含目标 id、字段名是什么、原始片段 |
| `decode` | 百分号 / 转义解码后的实际内容，确认字段是否真的能取到 |
| `flow` | 点击按钮，录下扩展内部在 `window` 上来回传的全部消息，并分步打印面板状态 |
| `isolated` | 从源码里抠出扩展当前的解析函数，直接在页面里跑，看它返回什么、耗时多少 |

两个环境事实（踩过的坑）：

- **Chrome 153 起官方版忽略 `--load-extension`**，日志里会写 `--disable-extensions-except is not allowed in Google Chrome`，扩展根本不会加载（页面里没有隔离世界、没有注入样式）。用 Edge 或 Chrome for Testing 才加载得起来。
- 未登录的临时配置打开 `https://www.douyin.com/?recommend=1` 会被重定向到 `/jingxuan`，并出现登录弹窗。所以推荐流的日常路径要靠用户真机验证，自动环境主要用于精选页 / 详情页。

- 重新加载扩展：`chrome://extensions/` → 该扩展 → 刷新按钮。
- 重新加载扩展后必须**完全刷新**抖音页面，否则旧 content script 会报存储上下文失效。

## 9. 用户偏好（协作时注意）

- 要**简洁**：多余的信息一律去掉（tag 文本、日期以外的内容、「最近识别」区块都被砍掉）。
- 要**对齐原生**：位置和视觉都希望跟抖音/Chrome 原生一致，不接受「差不多」。
- 强调**不干扰页面**：任何可能影响播放、滑动、加载的改动都需要谨慎，出问题要能快速回退。
- 会在真机上验证并反馈具体现象和报错行号，处理这类反馈时优先要可复现的定位手段。
- 关注**效率与 token 消耗**（曾吐槽一次小改动思考三分钟、模型响应慢），所以文档与回复尽量压缩。
